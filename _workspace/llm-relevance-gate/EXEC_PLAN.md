# EXEC_PLAN: llm-relevance-gate

- **타입**: feat
- **프로젝트**: project/dev-news
- **상태**: 배선 완료 / 기본 꺼짐 (모델 판정 불안정)

## 목표

차단 목록(filter-nondev-articles)으로 잡히지 않는 비개발 기사를 뺀다.
아래는 전부 AI가 소재라 개발 키워드에 걸리고 차단어도 없어서 통과한다:

  소니·워너, Anthropic 저작권 소송
  Fair Work Commission, 호주 부당해고 AI 조언 비판
  보코니대 학점 실험 (GPT-4o가 성적을 올렸다)
  영국 일자리 시장 분화

키워드로는 원리적으로 판별할 수 없다 — 어휘가 아니라 **글의 성격**이 문제다.

## 접근법

**요약 LLM 호출에 `분류` 필드를 하나 더 받는다. 추가 API 호출은 0회다** —
이미 모든 게재 후보에 대해 부르고 있는 그 호출에 줄 하나를 더 받는다.

  분류: 개발 | 주변 | 무관

`무관`만 게재에서 뺀다. `주변`은 남긴다 — 업계 동향은 개발자가 읽을 이유가 있고,
경계를 좁게 잡아야 오탐으로 진짜 기사를 잃지 않는다.

**실패 시 게재하는 쪽으로 기운다(fail-open).** 분류가 파싱되지 않거나 값이
이상하면 `개발`로 본다. 이 필드가 깨졌을 때 페이지가 비는 것이 훨씬 나쁘다.

**선별 순서 문제.** `build.py`의 `pick(top_n=20)`이 요약보다 먼저라, 20건 중
3건이 `무관`이면 그날 17건만 실린다. 그래서 여유 있게 뽑고(`top_n + overpick`)
요약하면서 게재 가능분이 `top_n`에 닿는 즉시 멈춘다.

**멈추는 것이 핵심이다.** 단순히 25건을 다 요약하면 LLM 호출이 늘 25회가 된다.
순서대로 요약하다 20건이 차면 중단하므로, 무관이 하나도 없는 회차의 호출 수는
지금과 같은 20회다. 무관이 나온 만큼만 더 부른다.

**무관 판정분은 seen에 넣는다.** 안 그러면 다음 회차에 다시 후보로 올라와
같은 기사에 LLM 호출을 반복한다.

## 단계별 계획

1. (RED) `tests/test_relevance.py` — 분류 파싱 · 값 정규화 · 누락 시 개발 ·
   무관만 제외 · 조기 중단 · 무관도 seen 등록
2. `news/summarizer.py` — PROMPT에 `분류` 필드, LABELS·`_parse` 확장,
   `summarize_all(stop_after=...)` 조기 중단
3. `build.py` — `overpick`만큼 더 뽑고, `무관` 제외 후 `top_n`으로 자르고,
   무관분을 seen에 등록
4. `config.yaml` — `scraper.overpick`
5. pytest 전체 → 커밋 → 아카이브

## 결과 (2026-08-31) — 배선은 됐지만 켜지 않았다

무료 `openai/gpt-oss-120b`의 판정이 안정적이지 않다. 실제 호출로 세 가지
분류 체계를 재봤다(총 30회).

| 시도 | 정확도 | 문제 |
|------|--------|------|
| 3분류 개발/주변/무관 | 5/10 | 대상 4건이 전부 `주변` — 게이트가 아예 안 걸린다 |
| **2분류 게재/제외** | **9/12** | `FedEx 피싱`(보안)을 오제외 1건 |
| 2분류 + 보안 지침 | 4/8 | 전부 `게재`로 기울어 게이트 미작동 |

프롬프트를 한 줄 손댈 때마다 분포가 통째로 흔들렸다. 3분류에서는 프롬프트에
"학교 성적 실험은 무관"이라고 명시했는데도 `개발`로 답했고, 2분류에 보안 예외를
한 줄 넣자 판정 자체를 포기하고 전부 게재로 답했다.

**그래서 최선안(2분류)으로 확정하되 `scraper.relevance_gate: false`로 두었다.**
끄면 `overpick`도 0이 되어 동작이 도입 전과 완전히 같다. 배선·조기 중단·seen
등록·fail-open은 전부 테스트로 고정돼 있어, 켜는 것만으로 동작한다.

**켜기 전에 할 일:** `LLM_MODEL`을 바꿔 같은 12건으로 재보는 것. Groq 안에서
모델을 고르는 것은 SPEC의 "Groq 전용" 제약에 걸리지 않는다.

**오제외가 가장 위험하다.** 2분류에서 `FedEx의 진짜 결제 문자가 피싱처럼 보인
이유`가 빠졌는데, 바로 직전 작업(filter-nondev-articles)에서 한국어 개발 어휘로
살려낸 기사다. 게이트를 켜면 그 수정이 무효가 된다.

## 완료 기준

- `분류: 무관`인 기사가 페이지에 실리지 않는다
- `분류`가 없거나 이상한 값이면 게재된다 (fail-open)
- 무관이 0건인 회차의 LLM 호출 수가 기존과 같다
- 무관 판정분이 seen에 남아 다음 회차에 재호출되지 않는다
- `--no-ai` 경로가 깨지지 않는다
- pytest 전체 통과
