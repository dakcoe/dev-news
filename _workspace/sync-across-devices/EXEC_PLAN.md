# sync-across-devices

보관함과 읽음 표시를 기기 사이에서 유지한다. 2026-09-19 구축.

## 왜

localStorage 에만 있어서 기기를 바꾸면 사라졌다. 폰에서 보관한 기사가 맥에서
안 보였다.

## 무엇으로

정적 사이트(GitHub Pages)에는 `client_secret` 을 둘 데가 없다. 그래서 Cloudflare
Worker 를 `api.dev-news.net` 에 붙이고 D1 에 저장한다.

```
worker/src/index.js      OAuth 교환 · 세션 · /sync · 계정 삭제
worker/schema.sql        app_user · session · bookmark · read_mark
worker/wrangler.toml     D1 바인딩 · 커스텀 도메인
news/template.html       SYNC_API 블록 (검색: SYNC_API)
```

## 되돌리지 말 것

**깃허브 토큰을 브라우저로 내리지 않는다.** Worker 가 교환하고 버리고, 브라우저엔
`HttpOnly; Secure; SameSite=Lax` 세션 쿠키만 준다. 사이트에 XSS 가 나도 깃허브
계정 권한이 새지 않는다.

**쿠키에 `Domain=` 을 쓰지 않는다.** host-only 쿠키라도 `dev-news.net` 페이지가
`api.dev-news.net` 으로 보내는 요청에는 실린다. 상위 도메인으로 넓히면 세션
토큰이 GitHub Pages 서버에도 매 요청 전달된다.

**scope 는 `read:user` 하나.** 저장소 별 누르기를 붙이려면 `public_repo` 가
필요한데, 그러면 동의 화면이 "공개 저장소 전체에 쓰기" 로 바뀐다.

**KV 가 아니라 D1.** KV 는 하루 쓰기 1,000건에 최종 일관성이고, 값이 통짜 JSON
이라 두 번째 기기가 첫 기기의 추가분을 덮어 지운다.

**쓰기는 변경분만.** 전체 목록을 보내면 같은 덮어쓰기 사고가 난다.
연산은 `bm+` · `bm-` · `rd` · `rd-` 넷이고 전부 멱등이다.

**읽기는 페이지 로드마다 1회.** localStorage 로 먼저 그리고 응답이 오면 조용히
맞춘다. 사용자 100명 × 하루 10번이면 1,000요청/일, 무료 한도의 1%.

**첫 동기화만 합집합, 이후는 서버가 정본.** 그래야 다른 기기에서 지운 게 여기서도
사라진다. 로그아웃은 로컬 사본까지 비운다 — 안 비우면 다음에 다른 계정이 로그인할
때 앞사람 기록이 그 계정으로 올라간다.

## 고친 결함

2026-09-20 외부 검토에서 셋이 나왔다. 셋 다 같은 뿌리다 — **전송 실패를 성공으로
처리했다.**

**읽음 해제가 서버에 안 갔다.** `syncQueueRead()` 가 추가만 보고 해제를 안 만들었다.
보관함 쪽(`syncQueueSaved`)은 처음부터 `bm-` 를 만들고 있었다. `rd-` 를 더했다.

**401 을 성공으로 쳤다.** 큐에서 꺼낸 변경을 그대로 버려서, 세션이 만료된 순간의
변경이 재로그인 뒤에도 돌아오지 않았다. 401 도 실패로 보고 큐에 돌려놓는다.

**못 보낸 변경이 있는데 서버 값을 씌웠다.** 시작할 때 `syncFlush()` 결과를 안 보고
`syncPull()` 로 갔다. 큐가 비었을 때만 정본을 받는다.
