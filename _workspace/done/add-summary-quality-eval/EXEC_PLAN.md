## 목표

요약 품질 회귀를 자동으로 잡는다. 모델이나 프롬프트를 바꿨을 때 나빠졌는지를
사람 눈이 아니라 지표로 판정한다.

## 배경

방금 `llama-3.3-70b` → `openai/gpt-oss-120b`로 바꿨는데, **품질 판정은 내가 눈으로
본 게 전부였다.** 자동으로 잡아주는 장치는 `FOREIGN_RE` 하나뿐이고 그마저
U+202F(공백)와 `→`를 오탐했다.

`LLM_MODEL`은 Actions Variables로 **코드 수정 없이 즉시 바뀐다.** 지금은 그렇게
바꿨을 때 품질이 떨어져도 아무도 모른다. 프롬프트를 고칠 때도 마찬가지다.

실측으로 확인된 결함 유형이 이미 있다.

| 유형 | 실제 사례 |
|------|-----------|
| 번역 누락 | `React useEventSource Hook: Server-Sent Events...` (gpt-oss, 관측됨) |
| 오역·비문 | `전문 메소도론가`, `있음을모르다하다` (llama) |
| 외국 문자 | `離任`, `プロトタイプ` (llama 계열 고질) |
| `없음` 누출 | 정상 요약 뒤에 "기술 스택 정보는 없음." 덧붙임 |

## 접근법

**두 층으로 나눈다.** 채점에 LLM 호출이 필요하니 매 푸시마다 CI에서 돌릴 수는
없다 — API 키·비용·시간 문제이고, 온도 0.3이라 결과도 매번 다르다.

1. **채점기(`news/core/quality.py`)** — LLM을 부르지 않는 순수 함수. 요약 dict를
   받아 문제 목록을 돌려준다. 고정 샘플로 CI에서 항상 검증된다.
2. **채점 스크립트(`scripts/eval_summary.py`)** — 고정 코퍼스를 실제 모델에 태워
   채점하고 기준선과 비교한다. 모델·프롬프트를 바꿀 때 사람이 돌린다.

**골든 코퍼스는 저장소에 커밋한다.** `content`를 더 이상 저장하지 않기로 했으므로
(drop-unused-content) 평가용 입력이 없다. 12건을 고정 픽스처로 박아두면 언제
돌려도 같은 입력으로 비교할 수 있다. **커밋 전에 반드시 마스킹을 거친다** —
안 그러면 이 파일 자체가 push protection에 걸린다.

**기준선은 정확값이 아니라 임계로 둔다.** 온도가 0이 아니라 실행마다 결과가
달라진다. 지표별 통과율을 기록하고, 허용 오차(10%p) 아래로 떨어지면 회귀로 본다.

## 채점 지표

| 지표 | 판정 | 근거 |
|------|------|------|
| `foreign` | 한자·가나·키릴 혼입 | 미게시를 유발하는 치명 결함 |
| `untranslated` | `ko_title` 한글 비율 < 15% | 영어 제목 방치 (실측 사례 있음) |
| `noinfo-leak` | `없음`이 문장에 남음 | 프롬프트 템플릿 누출 |
| `length` | 요약 60~500자 벗어남 | 너무 짧으면 정보 없음, 길면 잘림 |
| `incomplete` | `ko_title`·`summary` 결측 | |
| `residue` | 코드펜스·URL·마크다운 잔재 | 본문이 그대로 샌 흔적 |
| `echo`(참고) | 요약이 제목 어절을 과다 반복 | SPEC 1.3 "제목 복창 금지" |

`echo`는 GitHub 저장소 항목이 구조상 제목을 반복하게 되어 있어 하드 판정에서
빼고 참고 수치로만 낸다.
