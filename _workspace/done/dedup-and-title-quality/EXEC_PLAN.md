## 목표

수집물 자체의 품질 결함 3건을 고친다. 2026-08-30 최신 배치 20건 + 최근 10배치
196건을 직접 읽고 원인을 코드에서 확인한 결과다.

1. **같은 사건이 두 번 실린다.** 최신 배치에 캘리포니아 Linux 면제 기사가
   hackernews(tomshardware) · geeknews(hada.io) 두 건으로 나란히 실렸다.
   최근 196건 중 제목 유사도 0.5+ 쌍이 10개, 확실한 동일 기사가 4쌍인데
   `cross_source_count>=2`로 잡힌 건 **2건뿐**이다.

2. **긱뉴스가 원문 URL을 들고 오지 않는다.** `news.hada.io/topic?id=` 링크라
   URL 기준 중복 제거가 원천적으로 안 되고, 독자도 한 번 더 클릭해야 한다.

3. **번역제목이 원문에 없는 내용을 말한다.** `mvanhorn / last30days-skill`은
   요약(README 근거)과 제목 설명이 서로 다른 물건을 가리킨다. 원인은
   summarizer PROMPT가 저장소용으로 준 `"이름 — 한 줄 설명"` 형식을 모델이
   일반 문장 제목에도 적용하는 것. 같은 원인으로 블로그 글 URL 슬러그를
   저장소명처럼 붙인 사례(`anthropic / containment —`)도 나왔다.

## 접근법

**중복 판정은 URL 정규화 → 제목 유사도 2단으로 올린다.** 지금은 URL 완전일치
(`build.py:dedupe`)와 정규화 제목 앞 60자 완전일치(`scorer.py`) 둘 다 완전일치라
한국어 제목과 영어 제목이 같은 기사여도 절대 만나지 않는다.

| 단 | 기준 | 잡는 것 |
|----|------|---------|
| 1 | URL 정규화 (스킴·www·UTM·트래킹 파라미터·말미 슬래시 제거) | 같은 글의 다른 링크 표기 |
| 2 | 제목 토큰 자카드 ≥ 0.6 | 같은 글을 여러 소스가 물어온 경우 |

**한국어 제목은 유사도로 잡을 수 없다.** 토큰이 겹치지 않기 때문이다. 그래서
2번(긱뉴스 원문 URL 추출)이 1번의 절반을 담당한다 — 원문 URL만 확보되면
캘리포니아 Linux 같은 한/영 쌍이 1단에서 걸린다.

**중복은 버리지 않고 병합한다.** 점수가 높은 쪽을 남기고 `cross_source_count`를
올린다 — 여러 소스가 동시에 다룬 글은 실제로 더 중요하다는 기존 설계
(`scorer.py:44`의 `cross_source_count * 300`)를 살린다.

**긱뉴스 원문 URL은 RSS 안에 있는 것만 쓴다.** 토픽 페이지를 추가로 긁지 않는다
(hada.io는 python-requests에 403을 준다 — 로컬 실측). 원문을 못 찾으면 지금처럼
hada.io 링크를 그대로 쓴다. 즉 **실패해도 현행 동작으로 떨어진다.**

**프롬프트는 형식을 분기시킨다.** `"이름 — 설명"`은 제목이 고유명사뿐일 때만
쓰도록 조건을 좁히고, 문장형 제목에는 금지한다고 명시한다.

다만 1단계의 교차언어 매칭이 예상보다 잘 동작해 2단계의 필요성이 줄었다.
